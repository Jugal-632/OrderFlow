# Logs, metrics, and readiness

All five services use the shared JSON encoder. Records contain service/environment, correlation/request/event/order identity, Kafka topic/partition/offset, operation, outcome, duration in milliseconds, level and exception class where available. Missing context is null. The encoder deliberately excludes arbitrary formatted log messages, arguments, exception messages/stacks, HTTP bodies and unknown MDC fields: these can contain passwords, tokens, SQL parameters or connection credentials. Diagnose using the operation, error class, correlation ID and owning service's authorized APIs. Do not enable request-body or SQL bind logging in release deployments.

Servlet scopes restore previous MDC in `finally`; Kafka interception scopes wrap each record and restore after handling. Relays scope each immutable outbox record. Reactor context propagation carries Gateway correlation/request identity across thread changes. IDs belong in logs, never metric labels. The shared meter filter rejects identity-based labels.

Prometheus endpoints are on **separate internal management listeners**, bound to loopback by default: Gateway 9080, Auth 9081, Order 9082, Inventory 9083, Notification 9084. Scrape `/actuator/prometheus` from the same host/private monitoring network. `MANAGEMENT_PORT` and `MANAGEMENT_ADDRESS` configure deployment-specific private listeners; never route them through the public Gateway or expose them on a public security group. Application-port `/actuator` requests are rejected. Liveness `/actuator/health/liveness` checks process availability; readiness includes database/Redis and messaging/consumer state where applicable. Mutation readiness failure returns 503 with Retry-After; reads can still expose persisted state.

Metric families include `orderflow.http.duration` (method/template/outcome), `orderflow.consumer.duration` (success/error), `orderflow.operation.duration` (relay operation/outcome), `orderflow.confirmation.duration`, durable outbox counts/age/retries, DLT count, replay results, rejection count, and oldest pending-order age. Spring/Micrometer also expose JVM, pool and HTTP metrics. Operational SQL reads only the owning schema. Failed observations become NaN instead of fake zero backlog. Not-applicable gauges are NaN. Metrics are observations, not a replacement for durable database decisions.

In cloud deployments set `CLOUDWATCH_METRICS_ENABLED=true`, `AWS_REGION`, and `APP_ENV`. Micrometer CloudWatch2 exports every minute under namespace `OrderFlow`, with bounded service/environment dimensions. Use the task/workload IAM role and the SDK default credential chain; do not place access keys in source, application files or logs. The role needs `cloudwatch:PutMetricData` on `*`, constrained by `cloudwatch:namespace = OrderFlow`. Exporter failures must not roll back business transactions. Local tests verify the CloudWatch export request against a test client; they do not deploy AWS resources or claim a live AWS export.

Load `alerts.yml` into the private Prometheus server. `alertmanager.yml` specifies immediate grouping and a five-minute repeat; supply the deployment's approved receiver. Warning alerts begin when outbox age or PENDING/CANCEL_PENDING age exceeds 60 seconds; critical alerts begin at five minutes. Installing these configuration artifacts into a deployed monitoring server is deployment work, not performed by local tests.

Use `phase9-system/performance.json` for measured percentiles and invariants, not CloudWatch aggregation assumptions. Keep the environment, commit, workload, timestamps and source samples with each report. Never replace a measured failure with a target or manually edit a report to PASS.
